## Selected approach
A separate offline CLI imports a validated corpus into a FRESH explicitly named SQLite database, consumed by the existing live API/UI. This avoids the destructive seed/reset path and isolates the demo from real data. It reuses existing migrations, computeMarkers, buildBaseline, signedZ, markerMeta and baseline constants. Do not invoke processCall/recomputeElder: those create LLM requests or fabricate a zero repetition count when topics are absent. No schema or public API shape changes.

- Read exact current generator manifest/profile/canonical calls/timing only. Reuse and extract the existing audio source validation into a provider-independent reader where practical; preserve audio behavior. Reject changed source, symlinks and malformed paths before DB writes. Never read ground-truth files. Reader export loadTranscriptSource(inputDir) returns {manifest,profile,calls,timings}; existing loadAudioSource contract remains compatible.
- Import entry point importSyntheticTranscripts({inputDir,databasePath,apply=false}) returns {isSimulated:true,dryRun,elderId,callCount,markerCount,baselineCount,...}. Only --apply writes. Explicit database path required for apply; parent directory must already exist. Reject any existing DB/path/symlink and SQLite sidecar (-wal/-shm/-journal) collisions. Reject symlink ancestors and destination inside source. Reserve with exclusive creation/0600. Do not reset, remove or replace files. Failures may leave a new incomplete DB; choose another path. No network/credential loading.
- Open only the freshly reserved database with better-sqlite3, enable foreign keys, use existing migrate(); insert dataset rows in one transaction and always close. CWD web/ for migrations. No global DATABASE_PATH mutation in library. Existing DB never opened for writing by importer.
- Preserve canonical elder/call IDs, exact transcript and word timestamps, original dates, language and rounded duration seconds. Set every eligible data row is_simulated=1, audio_path NULL, status done. Use profile name/biography/family, preferredName Hal and primaryContact Linda for this fixed reviewed persona. Establish explicitly fictional sharing choices: summaries/speech true, fun facts/mood false on family and elder sides; no forged spoken consent event. No topics, fun facts, mood, nudges or repeat links.
- Compute seven marker rows per call from actual canonical utterances with existing pure computeMarkers. Add repeat_stories row value NULL/confidence na/z NULL (not analyzed). For seven speech markers use first BASELINE_N high-confidence nonnull chronological values, buildBaseline and signedZ with markerMeta concern and ABS_SPREAD_FLOOR or MIN_SCALE. Do not generate nudges. Pure baseline helpers shared with backend, no edits to backend pipeline/recompute.
- Summary is a plainly labeled extractive preview from first caller turn: `Transcript excerpt: “...”` (at most220 Unicode codepoints plusellipsis); no claim AI summarized it. Preserve raw transcripts privately in existing call storage, not family response.
- Shared web/lib/synthetic-demo.ts exports exact notice: `Synthetic transcript demo. Call timing is authored, not measured from audio. Call cards show transcript excerpts; summaries and repeat analysis have not been run.` Importer prepends it to about, blankline then biography. UI helper recognizes exact notice prefix; display it when imported profile matches and calls are simulated. Do not label all simulated demo sources as authored timing.
- Existing live route /elders/elder-synthetic-hal-bennett requires NEXT_PUBLIC_USE_FIXTURES=0. Optional NEXT_PUBLIC_DEMO_ELDER_ID override in web/lib/demo.ts (default existing elder-hal-demo) lets existing home/nav link to this elder; URL-encode path. Preserve default fixture behavior.
- Retold signal needs explicit unavailable status `not_analyzed` / `Not analyzed yet` for empty/all unavailable latest-week readings; do not coerce null/na into zero or fall back to earlier-week readings. Real analyzed zero retains usual; valid counts retain retold threshold. Conservative partial latest-week unavailable state is acceptable and tested. Add matching existing-style pill.
