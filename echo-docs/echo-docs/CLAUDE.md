# CLAUDE.md — Echo (HackPSU Fall 2026)

You are one of several Claude Code agents building **Echo** in parallel during a 24-hour hackathon. Humans on the team hold the phone, the secrets, and the final say. Read this file fully, then your workstream brief, then `docs/HANDOFF.md`, before touching code.

## What we're building (30 seconds)

An elder FaceTimes a friendly AI that remembers his past calls and his family's photos and questions. After each call, the family's web timeline gets a summary and "fun facts," and the system compares interpretable speech markers against **his own** baseline. If several markers drift for weeks, the family gets a gentle nudge to consider a check-up. Full spec: `SPEC.md` at the repo root.

## Non-negotiable rules

1. **Claims policy.** Never write code, comments, prompts, UI copy, or docs that say the product detects, diagnoses, screens for, prevents, or slows Alzheimer's/dementia, or assesses mental health. Use the approved phrasing in `docs/safety-and-copy.md`. If you are unsure whether wording is allowed, use the template text verbatim.
2. **Secrets.** Never print, `cat`, log, echo, or commit the contents of `.env`, `.env.local`, or any key. Refer to env vars by name only. If a command would display secrets, don't run it. `.env*` (except `.env.example`) must stay in `.gitignore`.
3. **Originality.** All code must be written during this event (after 2 PM Sat Oct 24). Do not copy code from the team's earlier projects (e.g., Brodie Coach / IvyHacks). Chert's generated starter and public library examples are fine; note them in the README.
4. **The contract is law.** `docs/contracts.md` defines every cross-workstream interface (endpoints, JSON, DB schema, env vars). Implement exactly that. To change it, see "Changing the contract" below.
5. **Stay in your lane.** Edit only directories your workstream owns (table below). Need something from another lane? Mock it locally and write a request in `docs/HANDOFF.md`.
6. **Simulated data is always labeled.** Any seeded or fake record sets `is_simulated = 1`, and any UI showing it shows a "Simulated" badge.
7. **Don't upgrade pinned versions** (`@livekit/agents` 1.8.0, Chert CLI 0.1.0-beta.10, Node 22.23.2/24.x) without human approval.
8. **Don't add scope.** No avatars, no extra participants in the LiveKit room, no auth providers, no extra languages beyond en/zh, no hosting migration, unless a human asks. P2 features are roadmap only.
9. **Verify, don't guess, library APIs.** Before using any `@livekit/agents` / `@livekit/rtc-node` / provider SDK API, confirm it in `node_modules/<pkg>` type definitions or the installed source. These APIs move fast; your training data may be stale. Note any surprises in HANDOFF.
10. **You cannot make FaceTime calls.** Anything that needs a real call is tested by a human. Ask for it explicitly with exact steps, then wait for their report.

## Workflow for every task

1. `git pull --rebase` on `main`. Read your section and "Requests" in `docs/HANDOFF.md`.
2. Work on branch `ws/<letter>-<short-name>`. Small commits, message prefix `[A]`/`[B]`/`[C]`/`[D]`.
3. Before claiming done: typecheck, lint, tests for your lane pass; for B/C also `scripts/smoke.sh`.
4. Merge to `main` as soon as an increment works (fast-forward or rebase; never force-push `main`). Push often — the repo must be public and show steady commits.
5. Update your section of `docs/HANDOFF.md`: what works, how to run it, what's mocked, known issues, what you need from others.
6. Stop and report to the human when a task's acceptance criteria are met. Don't wander into the next lane.

## Changing the contract

Only when unavoidable. In one dedicated commit prefixed `[contract]`: update `docs/contracts.md` **and** `web/lib/types.ts`, keep changes backward-compatible where possible (add optional fields rather than rename), and add a dated line to the "Contract changes" log in `docs/HANDOFF.md` naming affected workstreams. Tell the human in your reply so they can relay it.

## When blocked

Mock the dependency behind the contract (A: `MOCK_CONTEXT=1`; D: fixtures in `fixtures/demo/`), keep going, and log the blocker under "Requests" in HANDOFF. If the block is a missing secret, credential, Chert login, or physical call test, ask the human with exact steps.
