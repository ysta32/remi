# Workstream A — Call agent (`agent/`)

**Human owner:** Engineer 1. **You own:** `agent/`, `scripts/replay-failed.mjs`. **Read first:** `CLAUDE.md`, `SPEC.md` §5–6, `docs/contracts.md` §1, §3–4, `docs/safety-and-copy.md` §4.

## Mission
A LiveKit agent that FaceTime callers reach through Chert. It loads the elder's context, holds a warm memory-aware conversation, shows family photos as its video, asks the family question, records consent/safety events, and posts the transcript on hangup.

## Ground truth from Chert docs (do not contradict)
- Starter is generated by `chert new <name> --video` (Chert CLI `@trychert/facetime@0.1.0-beta.10`), Node 22.23.2 or 24.x, `@livekit/agents` 1.8.0, OpenAI Realtime. It publishes an animated face and does not consume caller video.
- `npm start` registers `AGENT_NAME`; the human runs `chert dev --agent <same name>` in a second terminal. The CLI does not start your code.
- Connect promptly, then `await ctx.waitForParticipant()` before opening the model session. Jobs may arrive with no caller (prewarm, `chert doctor`) — those must exit cleanly without API side effects.
- **Do not greet on job start.** The caller says hello first; then the agent greets.
- Exactly **one** audio publisher. Agent video must come from **the same participant** as the agent audio. Rooms allow two participants — no sidecar/avatar participants.
- Caller identity is `chert-bridge-<call ID>`; tracks `facetime-remote-audio`, `facetime-remote-video`. Warm-room job metadata has no call ID.
- Keep `record: false` and `deleteRoomOnClose: false` (Chert owns room cleanup).

## Rules specific to this lane
- Keep the generated starter's language and structure (ES modules). Add modules beside it (`context.mjs`, `instructions.mjs`, `video.mjs`, `tools.mjs`, `transcript.mjs`, `api.mjs`, `capture.mjs`); keep `agent.mjs` thin.
- Before using any API (`voice.AgentSession` options, Realtime turn detection / input transcription, `llm.tool` or equivalent, session events, `VideoSource`/`LocalVideoTrack`, `AudioStream`), open the installed type definitions under `node_modules/@livekit/*` and confirm names and signatures. Record what you found in HANDOFF under "A: verified APIs".
- Never read or print `.env.local`. If a variable is missing, tell the human its name.
- All HTTP from tools is fire-and-forget with short timeouts; the model must never wait on the network.
- `npm run check` must pass after every change.

## Tasks (in order; stop and report after each ✅ gate)

**A0 — Go/no-go (deadline 9:30 PM Sat) ✅ gate**
1. If `agent/` doesn't exist: tell the human to run `npm install -g @trychert/facetime@0.1.0-beta.10`, then `chert new echo-agent --video` at the repo root and rename the folder to `agent/` (or run it inside and move). Ensure `.gitignore` covers `node_modules/`, `.env`, `.env.*`, `!.env.example`, `tmp/`.
2. Ask the human to fill `agent/.env.local` (names in `docs/contracts.md` §1) and `chmod 600` it.
3. Run `npm install`, `npm run check`. Ask the human to run `npm start`, then `chert login`, `chert doctor`, `chert dev --agent echo-agent`, then place **two** FaceTime Video calls.
4. Ask the human to report: two-way audio? animated face visible? response latency feel? hangup clean? second call fresh? Write results to HANDOFF. If audio fails → tell the human to trigger the fallback decision (SPEC §17).

**A1 — Context + instructions**
- `api.mjs`: `getContext(elderId)` (1.5 s timeout), `createCall`, `postEvent`, `completeCall` with `Authorization: Bearer AGENT_API_TOKEN` against `ECHO_API_BASE`.
- `MOCK_CONTEXT=1` reads `agent/fixtures/context.json` (create it from `docs/demo.md` persona; must validate against `CallContext`).
- `instructions.mjs`: render the template in `docs/safety-and-copy.md` §4 exactly, including first-call consent block, `DEMO_MODE` variant, and `zh` language line. Add `node agent/scripts/render-instructions.mjs` that prints the rendered prompt for the fixture (for review).
- Fallback context on API failure: generic persona, no memory, still create the call later if possible.
- ✅ Acceptance: rendered prompts for en first-call, en returning, zh, and demo mode reviewed by the human.

**A2 — Transcript + complete**
- After the caller joins: `createCall` → `callId`; record `callStart = Date.now()`.
- Collect every conversation item (caller and agent) with text and `startMs`/`endMs` relative to `callStart`. Enable Realtime input transcription so caller text exists. If exact times aren't exposed, approximate from speech-start/stop events and note it in HANDOFF.
- On caller disconnect **and** in the shutdown callback (whichever first; guard against double-send): `completeCall` (3 s timeout, one retry), else write `tmp/failed/<callId>.json`.
- `scripts/replay-failed.mjs` POSTs every file in `agent/tmp/failed/` and deletes on 202.
- ✅ Acceptance (human call): after hangup, `/api/dev/status` shows the call `processing` → `done`; utterances look right.

**A3 — Photo as agent video**
- In `video.mjs`, replace the starter's animated-face frame source with an image renderer at the starter's existing resolution and frame loop. Default frame: soft background + "{APP_NAME}" + elder's preferred name. On `show_photo(photoId)`: fetch (or use prefetched) image bytes, letterbox, add a caption strip, crossfade ~300 ms if cheap, else hard cut. Prefetch all context photos at call start.
- Use `sharp` (or whatever image lib the starter already depends on) for decode/resize/compositing; convert to the frame format the starter's `VideoSource` expects.
- Video must be published from the same participant as audio, before the caller joins.
- ✅ Acceptance (human call, FaceTime Video): default card at pickup; photo appears within ~1 s of the agent saying it's showing it; caption readable on an iPhone.

**A4 — Tools**
- `show_photo`, `mark_family_question_asked`, `record_consent`, `report_safety_concern` with schemas from `SPEC.md` §6.3; each posts a `CallEvent` (fire-and-forget) and returns a short string to the model immediately ("shown", "noted").
- ✅ Acceptance (human call, first-call fixture): consent asked once and recorded correctly for a yes and for a no; family question asked once and credited; event rows visible in `/api/dev/status` or DB.

**A5 — Turn-taking and latency**
- Configure end-of-turn silence from `TURN_SILENCE_MS` (default 1000). Log per turn: caller-stopped → first agent audio (ms).
- ✅ Acceptance: human reads a sentence with a 700 ms mid-sentence pause and is not interrupted; median response latency < 1.5 s over 10 turns (log in HANDOFF).

**A6 — Caller audio capture (P1, behind `CAPTURE_AUDIO=1`)**
- Open an `AudioStream` on the caller's `facetime-remote-audio` track in parallel with the session; resample to 16 kHz mono; stream to `tmp/calls/<callId>.wav` (write header on close). Pass the absolute path as `audioPath`.
- If it causes glitches or errors, leave it off and document why.
- ✅ Acceptance: WAV plays back, duration ≈ call length; pipeline deletes it afterward.

**A7 — Mandarin (P1, only after 10 clean English end-to-end runs)**
- `language: zh` renders the zh line; verify voice quality; one human test call in Mandarin.

**A8 — Fallback web call (only if A0 fails or the human asks)**
- Make the same agent reachable from a browser (LiveKit's hosted agent playground or a minimal page using LiveKit's web components with explicit dispatch to `AGENT_NAME`). Verify which works with named dispatch before building.

## Do not
Greet on job start · publish a second audio track · add an avatar service · upgrade `@livekit/agents` · block the model on HTTP · log transcripts with secrets · let a missing API crash a live call.
